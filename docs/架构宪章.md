# 架构宪章（维护者：本鲸）

> 规则不是建议：能自动检查的，一律进 `scripts/check-imports.mjs`；不能自动检查的，改动时人工对照。

## 一、模块边界铁律（主人 2026-11-05 定）

**每个模块只对外提供标准接口，外部不得读取模块内部实现。**

落地细则：
1. 模块的"标准接口"= 该模块文件/目录的 **export**。外部只用 export，不假设其内部变量、闭包状态、文件布局。
2. **禁止跨模块深引用**：不允许 `import` 对方模块目录里的内部文件（如 `client/internal/xxx.js`、`host/repos/xxx-impl.js`），只允许经模块入口。
3. **禁止反向依赖**：`host` 不得 import `client`；`shared` 不得 import `client`/`host`；`client` 不得 import `host`（需要数据就走 HTTP 接口）。
4. **禁止读取构建产物/绝对路径**：源码里不得 `import` `dist/**`、不得用 `file:///` 绝对路径、不得 `require` 未声明的包。
5. 新增模块时同时给出：公开接口（导出清单）+ 内部实现（可以被替换、不承诺稳定）。
6. 改动别人模块的公开接口 = **破坏性变更**，必须同步改所有调用点，并在提交信息里写明 `BREAKING:`。

## 二、自动检查

`node scripts/check-imports.mjs` 检查：反向依赖、深引用、dist/绝对路径引用。
`npm test` 前先跑它（见 package.json 的 test 脚本），违规即失败。

## 三、改动门槛

tsc 0 错 → esbuild 0 错 → selftest 通过 → npm test 全过 → node --check 通过。缺一不提交。

## 四、重大变更有方案再动手

先出方案（不改代码）→ 主人点头 → 小步实施（每步 ≤2 文件、可回滚）→ 验收 → 决策记入 `docs/adr/`。
