# ADR 0002 · 模块接口契约的可执行化

- 状态：已采纳（2026-11-06）
- 决策者：小鲸（架构负责人）
- 相关文件：`scripts/check-imports.mjs`、`scripts/gen-module-index.mjs`、`docs/模块接口清单.md`、`docs/架构宪章.md`、`package.json`（files 白名单）

## 背景

主人定下铁律：**每个模块只对外提供标准接口，外部不得读取模块内部实现**。仅靠文档约束不够——需要：

1. 有**清单**说明每个模块到底暴露了什么（契约可见）；
2. 有**检查**能在越界时自动失败（契约可执行）；
3. 有**打包边界**防止运行数据/内部源码流出（契约可分发）。

## 决策

### 1. 接口清单自动生成（而不是手写）
`scripts/gen-module-index.mjs` 扫描 `src/{host,client,shared}` 的顶层 export，生成 `docs/模块接口清单.md`（当前 88 模块 / 492 导出）。
- **理由**：手写清单必然过时；从源码生成才能与实现同步。
- **代价**：接口变化后需重跑脚本；计划把 `--check` 模式接入 `npm test`（待拆分批次完成后启用）。

### 2. 边界检查三条硬规则（`check-imports.mjs`，已接入 `npm test`）
- 反向依赖：`host` 不引 `client`；`shared` 不引 `client/host`；`client` 不引 `host`；
- 深引用/绝对路径：不得引用 `dist/**`、`file:`、绝对路径；
- **路由越界**（本次新增）：`src/host/routes/**` 不得直接 import `repos/`、`store.js`、`cache.js`、`chat-core.js`、`prefs.js`——必须经 `ports` 注入；
  > 2026-11-07 修订：`chat-core.js` 列为**受控例外**。它是无状态的 chat 领域纯函数
  > （常量 / 归一化 / 消息拼装 / 读请求体），不持有存储、不做 I/O 以外的事；把 12 个纯函数
  > 塞进端口注入只增加仪式、不增加隔离收益。仍在禁令内的是 **store / repos / cache / prefs /
  > story-repo / data 实现**——这些才是「改实现会波及路由」的真依赖。
- **循环风险**（本次新增）：`src/client/**` 子模块不得反向 import 组件入口 `client.ts`。

### 3. 打包白名单（`package.json.files` 精确化）
从「整个 `data`」改为逐项白名单（`data/story`、`data/culture`、`poems.json` 等），把 `data/cache`、运行数据、`config.json`、`src/` 排除在包外。
- **理由**：一次实测发现 20 个运行缓存（可能含对话内容）会进包，属隐私风险。

## 后果

- 加新模块：写实现 + 导出 + 重跑清单；不需要审批。
- 改别人模块的公开接口：必须同步调用点，提交信息写 `BREAKING:`，并重跑清单。
- 绕过 `ports` 直连仓储的路由会被 `npm test` 直接拦下。
- 包体积从 124 文件/18.6 MB 降到 97 文件/16.5 MB，且不含任何运行数据。

## 未采纳的替代方案

- **ESLint import 规则**：项目无 ESLint 依赖，引入成本高于自写脚本（现在只需 `npm test` 前跑一个 node 脚本）。
- **tsconfig paths 限制**：只能控制解析，不能表达"反向依赖"语义。
- **运行时接口校验（Proxy）**：增加运行时开销，且 TS 编译期已能覆盖大部分误用。
