# 语音聊天方案：云端 TTS/ASR + 离线兜底（设计稿）

> 目标：把现在的"语音助手"体验做到接近真人对话——**首音频 <1s、说完 <1s 出字、说话能打断朗读**。
> 决策：**云端 TTS/ASR 为主（按量付费）**，**离线兜底**（edge-tts / 浏览器朗读）。
> 状态：设计稿，未实施。下面每节都标了"已确认/待验证"。

## 一、前置结论（技术前提）

- **DSH 插件 webServer 只提供 HTTP 路由注册**（`ctx.webServer.register({ kind, path, handler })`），**没有 WebSocket 通道**（已查 `dsh-host-webserver`）。
- 所以 **客户端到插件**只能是 HTTP；**真·流式 ASR（边说边出字）在插件内做不到 WebSocket 直连**。
- 解法：**伪流式**——客户端把录音切成 **1.5–2 秒**小段并发上传，云端 ASR 每段一句话识别；拼起来就是"边说边出字"，端到端延迟约 0.5–1s。这条是本次设计的核心取舍。

## 三、架构

```
[浏览器]
  ├─ 录音（1.5–2s 小段，VAD 端点仍在客户端）
  │    └─ POST /asr/seg  （每段一次，最多 3 段并发）──→ [插件 host]
  │                                              └─ cloud-asr.ts ──→ 云端 ASR HTTP
  │                                                    └─ 失败/超时 → 旧 ASR（现有）→ 离线兜底
  └─ 聊天（/chat-stream 不变）
       └─ TTS：POST /tts?provider=cloud ─────────→ [插件 host]
              cloud-tts.ts ──→ 云端 TTS HTTP（mp3 字节）
                    └─ 失败 → edge-tts（现有 python）→ 浏览器朗读（现有）
```

- **TTS 打分块并发**：客户端把回复切成 ≤56 字块（现有 `splitForTts`），**首块单独最高优先级**，其余 2–3 块并发预取；云端合成单块约 200–400ms。
- **ASR 伪流式**：录音段 1.5–2s（比现在的 6s 短），段间滑动衔接；识别结果按顺序拼接，交给现有意图/聊天链路。
- **打断**：朗读期间麦克风持续开（现有），检测到人声音量骤增 → `stopTts()` → 立刻进入识别（**唤醒门保持"随时可说"**）。

## 四、配置与安全

`config.json` 新增（**只存 Key，不随包分发**）：
```json
{
  "cloudVoice": {
    "provider": "volcengine",          // volcengine | aliyun | off
    "tts": { "appId": "", "accessToken": "", "cluster": "", "voice": "zh_female_..." },
    "asr": { "appId": "", "accessToken": "", "cluster": "" },
    "fallbackToLocal": true            // 云端失败是否回退 edge-tts/浏览器
  }
}
```
- Key 只从 `config.json` 读（与现有 DeepSeek/旧 ASR一致），**导出/导入备份绝不包含**；
- 每段请求带大小上限；云端超时 8s；**成本熔断**：单日合成字数/识别时长超上限自动停用云端（配置项 `dailyBudgetChars` / `dailyBudgetSeconds`）。

## 五、成本估算（按主人日常）

- 聊天 TTS：每天约 3,000 字 → **约 ¥0.3/天**（¥9/月）；
- 语音识别：每天约 10 分钟 → **约 ¥0.25/天**；
- 合计 **约 ¥0.5–0.6/天**，有额度上限兜底，不会失控。

## 六、实施步骤（文件级，分三阶段）

### 阶段 1：云端 TTS（最见效，先做）
1. `src/host/cloud-tts.ts`：火山/阿里 HTTP 合成（mp3 字节），端口化（`CloudTtsEngine`）；
2. `src/host/routes/tts.ts`：`?provider=cloud` 优先云端，失败回退 edge-tts，再失败 501（客户端降级浏览器）；
3. `src/host/config.ts`：读 `cloudVoice` 配置 + `dailyBudgetChars`；
4. `src/client/voice.ts`：合成请求带 provider，失败链更新；
5. 成本计数：`~/.dsh-chubby-whale/cloud-usage.json`（日字数），超限即回退。

### 阶段 2：云端 ASR 伪流式
1. `src/host/cloud-asr.ts`：一句话识别（HTTP，base64 音频）；
2. `src/host/routes/asr.ts`：`?provider=cloud` 优先，失败回退旧 ASR；
3. `src/client/voice.ts`：录音段 **6s → 2s**（可配），段并发上限 3；
4. 识别结果按序拼接 + 现有回声过滤/意图路由。

### 阶段 3：打断与体验打磨
1. 朗读中人声检测 → `stopTts()`（需阈值调参，避免误打断）；
2. 说话结束判定从 900ms → 600ms（可配）；
3. 首块 TTS 优先级 + 预取并发 2–3 块。

## 七、风险与未验证项

| 风险 | 说明 |
| --- | --- |
| 云端网络抖动 | 已有兜底链（edge-tts/浏览器）；云端故障不影响可用性 |
| 伪流式延迟 | 2s 段 + 200–400ms 合成，端到端 0.5–1s，**不是真流式** |
| 成本失控 | 日预算熔断 + 本地用量计数 |
| Key 安全 | 只存本地 config.json；导出/导入排除 |
| 供应商账号 | 需要主人开通火山/阿里账号并给 Key（**本鲸没有账号**） |
| 真机验证 | 本机可测浏览器侧；云端接口要真 Key 才能打通 |
