# 发布流程（Gitee / GitHub / npm 三处保持一致）

> **口径（2026-11-07 复核）**：Gitee 必发；GitHub / npm 可达时同步同一版本。
> 细则以 [发布规范.md](发布规范.md) 为准（含 `tools/gh-sync.mjs` 绕开 git 端点、npm 202 异步可见等实测细节）。
>
> 唯一真源：本地 `package.json` 的 `version`。三个渠道只是「读」它，谁不一致就用下面步骤对齐。

## 一、跨平台前提

发版流程**只用 Node**，不依赖 PowerShell / bash 特性（Windows / Linux / macOS 同一条命令）：

```bash
cd <仓库目录>
node tools/release.mjs check        # 构建 + 全链测试 + 发版一致性自检
```

- 脚本内部用 `spawnSync(程序, argv数组)`，不拼 shell 字符串；Windows 上 npm 自动用 `npm.cmd`；
- 任何一步失败即停，不静默继续；`check:tag` 会在打 tag 后用严格模式再核一次。

> 插件**运行时**也没有 shell 依赖：唯一的外部命令是 Windows 分支下的 `taskkill`（POSIX 走信号，
> 2026-11-07 起 POSIX 也有 SIGKILL 第二级补刀），其余全是 Node API。

## 二、发版前的自检（手工版，等价于 check）

```bash
npm run build
npm test
npm run check-release            # package.json / 客户端 VERSION / dist / CHANGELOG / tag 五处一致性
npm run check-release:strict     # 打 tag 之后、推之前用（要求 tag 已存在）
```

`npm run version:check`（`tools/version-check.mjs`）可额外核对本地 / Gitee / GitHub / npm 四处版本与 npm 包内 `dist/client.js`。

## 三、升版本并发布

```bash
# 1) 改版本号（改 package.json；构建时会同步生成 src/client/version.ts）
npm run build

# 2) 提交 + 打 tag（tag 名 = v<version>）
git add -A
git commit -m "release: <version> —— <一句话>"
git tag -a "v<version>" -m "v<version>"

# 3) 三端发布（一条命令；也可以按下面分步）
node tools/release.mjs push     # 推 Gitee main+tag → GitHub 同步 → npm publish → 轮询 latest
```

分步等价命令：

```bash
git push origin main
git push origin "v<version>"
node tools/gh-sync.mjs                                   # GitHub（走 API，本机 github.com 常不可达）
npm publish --registry=https://registry.npmjs.org        # npm（必须显式官方源；本机默认源是镜像）
node tools/release.mjs poll                              # 轮询 dist-tags.latest，确认已可见
```

## 四、各渠道的特别注意

| 渠道 | 方式 | 注意 |
| --- | --- | --- |
| Gitee | `git push origin main` + tag | 正常推送；历史曾被重写过一次（清密钥），老克隆要重新拉 |
| GitHub | `node tools/gh-sync.mjs` | 本机 `github.com` 常不可达，脚本走 `api.github.com`；凭据取自 git 凭据管理器 |
| npm | `npm publish --registry=https://registry.npmjs.org` | 必须显式指定官方源；token 需带 Bypass 2FA；返回 202 后要轮询 `dist-tags.latest` 才算可见 |

## 五、npm token 的存放

```text
~/.npmrc → //registry.npmjs.org/:_authToken=***
```

细粒度 token，建议只授权 `dsh-chubby-whale` 这一个包，并定期轮换。

## 六、常见坑与坏了怎么办

1. **npm publish 报 403 要求 2FA**：token 没勾 Bypass 2FA；或账号是 auth-and-writes 模式，需加 `--otp=6位`。
2. **npm 上出现 0.0.0-stage**：那是 npm 的「暂存发布」占位版本，正式版本通过验证后会覆盖 latest；占位版已标记 deprecated。
3. **GitHub 上传失败（中文文件名）**：`git ls-files` 默认转义路径，脚本里已用 `-c core.quotePath=false` + `-z` 处理。
4. **npm 包体积约 9 MB**：主要来自 `data/story` 17 本说书（30 MB 源文件压缩后 9 MB）。若嫌大，可把说书拆成可选数据包（未做）。
5. **版本号 / tag 不一致**：先 `npm run check-release` 看是哪一处；若 npm 尚未发布，可删 tag 重建
   （`git tag -d vX && git tag -a vX ... && git push -f origin vX`），否则按 ADR-0006 处理并在 CHANGELOG 记录。
6. **npm 已发布但装不上**：`node tools/check-installed.mjs --dir <解包目录>` 查文件集合 / 入口可达 / client.js 一致。
