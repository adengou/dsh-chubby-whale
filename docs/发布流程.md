# 发布流程（Gitee / GitHub / npm 三处保持一致）

> 唯一真源：本地 `package.json` 的 `version`。
> 三个渠道只是“读”它，谁不一致就用下面两步对齐。

## 一、发版前的自检

```powershell
cd C:\Users\eric8\.dsh\plugins\dsh-chubby-whale
npm test                 # 文字体检 + 39 项单测
npm run version:check    # 本地 / Gitee / GitHub / npm 四处版本 + npm 包内 dist/client.js
```

输出示例（全 ✓ 才继续）：

```
✓ 本地 (package.json)    1.0.0
✓ Gitee  main           1.0.0
✓ GitHub main           1.0.0
✓ npm    latest         1.0.0
✓ npm 包内 dist/client.js 与本地一致
✅ 三处版本一致
```

## 二、升版本并发布

```powershell
npm version patch        # 或 minor / major；会自动改 package.json 并建一次提交
npm run build            # 重新打前端包
git push origin main     # ① Gitee
npm run sync:github      # ② GitHub（本机连不上 github.com，走 API 只传差异）
npm publish --registry=https://registry.npmjs.org   # ③ npm
npm run version:check    # 再验一次：四处应全部等于新版本
```

## 三、各渠道的特别注意

| 渠道 | 方式 | 注意 |
| --- | --- | --- |
| Gitee | `git push origin main` | 正常推送；历史曾被重写过一次（清密钥），老克隆要重新拉 |
| GitHub | `npm run sync:github` | 本机 `github.com` 被墙，脚本走 `api.github.com`；凭据取自 git 凭据管理器 |
| npm | `npm publish --registry=https://registry.npmjs.org` | 必须显式指定官方源（本机默认源是 npmmirror 镜像）；token 需带 Bypass 2FA |

## 四、npm token 的存放

```
~/.npmrc → //registry.npmjs.org/:_authToken=***
```

细粒度 token，建议只授权 `dsh-chubby-whale` 这一个包，并定期轮换。

## 五、常见坑

1. **npm publish 报 403 要求 2FA**：token 没勾 Bypass 2FA；或账号是 auth-and-writes 模式，需加 `--otp=6位`。
2. **npm 上出现 0.0.0-stage**：那是 npm 的“暂存发布”占位版本，正式版本通过验证后会覆盖 latest；占位版已在 npm 上标记 deprecated。
3. **GitHub 上传失败（中文文件名）**：`git ls-files` 默认转义路径，脚本里已用 `-c core.quotePath=false` + `-z` 处理。
4. **npm 包体积 9 MB**：主要来自 `data/story` 17 本说书（30 MB 源文件压缩后 9 MB）。若嫌大，可把说书拆成可选数据包（未做）。
