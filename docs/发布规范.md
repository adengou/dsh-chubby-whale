## 一、版本号规则

采用语义化版本 `主.次.修订`。

| 位置 | 升级条件 | 示例 |
| --- | --- | --- |
| 主 | 不兼容变更：插件导出形状、配置键、数据格式、HTTP 接口不兼容 | 1.0.1 → 2.0.0 |
| 次 | 行为变化：新增能力、交互调整、修缺陷但用户可感知 | 1.0.1 → 1.1.0 |
| 修订 | 不改变行为：文档、注释、构建脚本、测试、内部重构 | 1.0.1 → 1.0.2 |

两条口径：

- 只有行为变化升次；纯修复、文档、测试、构建升修订。拿不准时按修订处理。
- 未发布改动可以攒在 `main` 上，版本号暂不动；正式发版时才升号、改 CHANGELOG、打 tag。

版本号存在两处，必须相等：

1. `package.json` 的 `version`——唯一真源，发版只改这里；
2. `src/client/version.ts` 的 `VERSION`——**生成文件**，由 `scripts/gen-version.mjs` 在构建前用 `package.json` 生成，文件头标注「自动生成，请勿手改」。`src/client/styles.ts` 只做 re-export（`export { VERSION } from './version.js'`）。

因此「改两处版本号」的正确操作是：改 `package.json` → 跑 `npm run build`（或 `node scripts/gen-version.mjs`）让脚本同步第二处；**禁止手改 `version.ts`**，手改会在下次构建被覆盖并造成漂移。`npm test` 第 [14] 组已断言两者一致（2026-11-06：client=1.0.1，pkg=1.0.1）。

README 不写死版本号；若以后写入，必须与 `package.json` 相同，否则视为发布阻断项。

## 三、提交信息模板

格式：

```
<type>(<scope>): <摘要>

<动机与行为变化；关联坑号或文档>
```

- type：`feat` / `fix` / `docs` / `build` / `test` / `refactor` / `chore`
- scope：`client` / `host` / `data` / `tools` / `docs` / `release`
- 摘要不超过 50 字，用规范书面语，不用网络流行语。

格式示例（不是仓库内提交原文）：

```
fix(host): 写盘失败打印 WRITE-FAIL 日志

磁盘满或权限问题此前静默失败，事后无法定位；关联 docs/坑.md 与 docs/待重启生效.md 第 5 条。
```

## 四、发布渠道（2026-11-07 起：Gitee 主渠道 + 条件同步）

> **2026-11-07 主人指令**：默认仍以 Gitee 为唯一主渠道；**若 GitHub / npm 可达，则同步发布最新版本**。
> 本机实测（同一时刻测的，不是推测）：
> - `github.com` 的 git 端口被重置（`Recv failure: Connection was reset`，HTTP 000）；`api.github.com` 返回 200 → **GitHub 只能走 API 上传**。
> - `registry.npmjs.org` 可达，`npm whoami` = `adengou`，`npm ping` PONG → 可发布。

### 4.1 Gitee（默认，必做）

```bash
git push origin main --tags
```

- `origin` 指向 `https://gitee.com/adengou/dsh-chubby-whale`。
- 回滚一律用 `revert`，禁止 force push `main`。

### 4.2 GitHub（API 通道，可达时同步）

```bash
# 凭据：git 凭据管理器里的 github.com PAT（不落盘、不打印）
GH_TOKEN=<pat> node tools/gh-sync.mjs --dry-run   # 先看差异
GH_TOKEN=<pat> node tools/gh-sync.mjs             # 真传（Git Data API，逐文件 diff）
```

- 上传后**必须建 tag**（GitHub API 不会自动带 tag）：`POST /repos/{owner}/{repo}/git/refs`，`ref=refs/tags/vX.Y.Z`、`sha=<main 的 commit>`。
- 校验：`GET /repos/{owner}/{repo}/contents/package.json?ref=vX.Y.Z`，解 base64 后 version 必须等于 `package.json`。
- 2026-11-07 实测：`main` = `77d1536`（246 文件），tag `v1.1.48` 指向同一提交，版本核对 1.1.48 ✅。

### 4.3 npm（可达时同步）

```bash
npm publish --registry=https://registry.npmjs.org --no-audit --no-fund
```

- **返回 HTTP 202 是正常的**：npm 采用异步处理，`registry.npmjs.org/<包>/<版本>` 在 1–5 分钟内才可能返回 200；
  立即 `npm view` 会看到旧版本，**不要当成失败**（2026-11-07 实测：202 接收 → 约 4 分钟后可见）。
- 复核口径：`npm view dsh-chubby-whale version --registry=https://registry.npmjs.org` 与 `dist-tags.latest`。
- `package.json` 的 `files` 白名单决定包里内容（2026-11-07 实测 128 文件 / 17.1 MB）。

### 4.4 失败处理

- 任一外渠失败**不影响 Gitee 发布**；把现象（HTTP 码 / 报错原文）写进 CHANGELOG 的「未发布」或批次表，不粉饰。
- 冻结项：`npm publish` 之外的 npm 写操作（如 `npm deprecate`）仍需单独确认。

## 五之二、发版一致性自检（2026-11-07 事故后新增，**推之前必跑**）

```bash
npm run build            # 确保 dist 与源码同版本
npm run check-release    # 版本号 / CHANGELOG / dist / tag 四处一致性
```

打 tag 之后、推远端之前再跑一次严格模式（缺 tag 即失败）：

```bash
npm run check-release:strict
```

**为什么加这道门**：2026-11-07 一次发版，发布脚本因文案里反引号嵌套报语法错误，但同一命令里
后续的 `git commit / tag / push` 照常执行，于是打出了「tag = v1.1.72、package.json 还是 1.1.71」的坏 tag
并推到了 Gitee。事后补提交 + 重建 tag 才修好。教训两条：
1. 发布脚本单独跑、确认 exit 0 再执行 commit/tag/push；
2. 推之前跑 `npm run check-release`，它会把包/客户端/dist/CHANGELOG/tag 五处不一致逐条列出来。


## 六、回滚流程

| 情形 | 操作 |
| --- | --- |
| 已提交、未打 tag | `git revert <commit>`，推 `main` |
| 已打 tag、未推送 | `git tag -d vX.Y.Z`，修正后重打 |
| 已推送 tag | 按下方命令处理 |

```bash
git tag -d vX.Y.Z
git push origin :refs/tags/vX.Y.Z
# 修正后重打并推送
git tag -a vX.Y.Z -m "vX.Y.Z"
git push origin main --tags
```

- 禁止 force push `main`：历史曾因清理密钥重写过一次，老克隆必须重新拉取；回滚一律用 `revert`，保留历史。
- 回滚后在 CHANGELOG 增加「回滚说明」一节，写原因与影响范围；不改写已发布版本的记录。

## 七、版本一致性自检

```bash
node -e "const fs=require('fs');const p=JSON.parse(fs.readFileSync('package.json','utf8'));const m=/VERSION\s*=\s*'([^']+)'/.exec(fs.readFileSync('src/client/version.ts','utf8'));console.log('package.json='+p.version+'  version.ts='+(m&&m[1]));process.exit(m&&m[1]===p.version?0:1)"
```

退出码 0 表示两处一致。另可核对 tag：`git tag --list` 的最新 tag 应与 `package.json` 同版本（当前 `v1.0.1`）。
