# 语音输入输出算法（听力 / 混音 / 串线 / 答非所问 / 延迟）

> 2026-11-04 第二版。第一版只做了阈值和计量，这一版补上**物理闭麦**、**分级闸门**、
> **并发纪元**、**端到端延迟打点**。目标：该听的一定听到，不该听的一句都不进来，
> 回来的答案只属于最新那一句。

## 一、五个问题 ↔ 五个机制

| 问题 | 现象 | 机制 |
| --- | --- | --- |
| 听力障碍 | 说话没反应 | dBFS 电平判定 + 双阈值滞回 + 每段计数器复位（自适噪声底只在 APE 路径，classic 是绝对阈值） |
| 混音 | 鱼的声音和自己的声音叠在一起 | **物理闭麦**：播放时 `track.enabled=false` |
| 串线 | 上一句的回答冒出来盖住这一句 | 对话纪元 `chatEpoch`；识别单飞 `asrBusy` **尚未实现**，当前靠录音段串行 + 段号去重兜底 |
| 答非所问 | 听错字 / 理解偏 | 唤醒词剥离 + ASR 容错提示 + 回声文本比对 |
| 反馈太慢 | 说完要等 5–10 秒 | 三段提速 + 气泡状态（预合成垫音已移除，见文末校对） |

## 二、采集链（耳朵）

```
麦克风 get(echoCancellation + noiseSuppression + autoGainControl, 单声道)
  → AnalyserNode(fftSize 1024, smoothing 0)
  → 每 60ms 读时域 RMS → dBFS
  → 电平判定：classic 端点走**绝对阈值**（`CLASSIC_SPEECH_DB` / `MUTED_SPEECH_DB`，不学噪声底）；
    APE 路径才做自适应噪声底与 margin 滞回，参数以实现 `client/ape.ts` 为准
  → speechMs ≥ 150ms 且 quietMs ≥ 700ms（常量 `EARLY_STOP_QUIET`）→ 判说完 → MediaRecorder.stop()
  → 上传 ASR（当前：上一段上传完才排下一段 + 段号去重；单飞 asrBusy 尚未实现）
```

要点：

- **噪声底自己学**：环境一变阈值跟着变；
- **滞回双阈值**：起判高防误触，停判低防切句；
- **每段复位**：`startChunk()` 必须清 `speechMs/quietMs`（不清会"完全听不到"，这是修过的真 bug）；
- **单飞**：ASR 同时只允许一个在途，宁可丢一段也不让结果乱序。

## 三、闭麦链（防混音与自言自语）——四层从硬到软

```
第 1 层  物理闭麦   播放开始 → micTrack.enabled = false（浏览器不再采样）
                  播放结束 + 700ms 回声静音窗 → enabled = true
第 2 层  逻辑闸门   【设计目标，尚未实现】ttsPlaying || ttsQueue.length>0 || storyNarrating → 不上传
                  现状：上传前只判静音/APE/mutedUntil/体积；混音靠第 1、3、4 层兜底
第 3 层  静音窗     TTS 结束 700ms 内录到的音频直接丢
第 4 层  文本比对   ASR 结果与最近 6 句自己说过的话比对：
                  互为子串或逐字命中 ≥60% → 判回声丢弃并打日志
```

第 1 层最硬：AEC 只是"估算"，`track.enabled=false` 是"根本没有信号"。

## 四、并发链（防串线与占线）

```
对话：myEpoch = ++chatEpoch → await → if (myEpoch !== chatEpoch) return
识别：目标为 if (asrBusy) return；**当前未实现**，现状是「上一段上传完才排下一段」+ 录音段号去重
优先级：P0 主人提问（可打断一切）> P1 说书/念诗 > P2 定时提醒（只排队）
占线保护：busy 期间拒绝新提问并给气泡提示（语音场景排队 = 看起来卡死）
```

详见 `docs/并发纪律.md`。

## 五、延迟：三段分别优化

| 段 | 原来的问题 | 现在 |
| --- | --- | --- |
| 说完 → 判定 | 静音 700ms 才收尾 | **700ms**（常量 `EARLY_STOP_QUIET`） |
| 判定 → 识别 | 录音段含大量前导静音 | 录音上限 6000ms（`WINDOW_MS`）；短句门槛 1200 字节 |
| 结果 → 出声 | 等整段回复 + 首段合成 | **气泡即时反馈**「听到：…｜本鱼在想…」（垫音已移除）；回复到达即开播 |

`__chubbyWhale.lat` 是实测数值：

```js
__chubbyWhale.lat
// { asrMs: 1834, chatMs: 2210, firstAudioMs: 0, updates: 3 }
```

- `asrMs` 大 → 网络 / ASR 服务慢
- `chatMs` 大 → 模型慢（max_tokens 已压到 260）
- 两个都不大但体感慢 → 等待期没有反馈，气泡状态解决

## 六、答非所问的三道处理

1. **唤醒词剥离**：`大肥鱼，讲个笑话` → `讲个笑话`，不把唤醒词喂给模型；
2. **ASR 容错提示**：告诉模型"这是语音识别，可能有错字/同音字/口水词，按最合理意思理解，不要复述、不要纠正、不要反问"；
3. **回声丢弃**：见第三节第 4 层 —— 同时解决"自言自语"和"把鱼的话当主人的话"。

## 七、状态机

```
       ┌──────────── idle ────────────┐
       │                              │
  用户说话                       播放结束 +700ms
       ▼                              │
   listening ──(700ms 静音)──► thinking ──(回复到达)──► speaking
       ▲                              │                  │
       └──────────(P0 打断)───────────┴──────────────────┘
```

- `listening`：只采集不上传；
- `thinking`：麦克风仍开，但逻辑闸门会挡掉自己的垫音；
- `speaking`：**物理闭麦**。

## 八、自检与调参

```js
__chubbyWhale.ear   // { db, noiseDb, onsetDb, speechMs, quietMs, calibrating }
__chubbyWhale.lat   // { asrMs, chatMs, updates }
__chubbyErrors      // 客户端异常（含被就地拦下的渲染异常）
```

| 现象 | 先看 | 处理 |
| --- | --- | --- |
| 说话没反应 | 说话时 `db` 是否 > `onsetDb` | 不高于 → 麦克风/设备问题；一直贴近 → 调高 `ONSET_DB` |
| 句子被切一半 | 句中 `quietMs` 是否已到 700 | 把 `EARLY_STOP_QUIET` 提到 900 |
| 还会自言自语 | 有无「丢弃回声」日志 | 有 = 拦住了；没有 = 查 AEC 是否被浏览器禁用 |
| 反应慢 | `lat.asrMs` vs `lat.chatMs` | 哪个大就是哪段瓶颈 |
| 答非所问 | 气泡里「听到：xxx」是否本来就错 | 识别错 → 换 ASR/补词表；识别对 → 提示词问题 |

## 九、已知边界（诚实写明）

- **ASR 不是流式的**：旧 ASR是文件式接口，必须等一段说完才上传，延迟下限 ≈ 700ms 判定 + 网络往返。
- **物理闭麦 = 不能边听边说**：鱼在播时主人插话会被忽略（有意取舍：宁可忽略插话，也不要混音）。
- **回声文本比对是启发式**：对"整句重复"有效；主人恰好说出与鱼刚说的一模一样的话会被误杀（概率低但存在）。
- **参数是常规室内近场值**：未做多人、远场、强噪声实测。
- **未做压力测试**：并发规则来自实际故障复盘，不是理论验证。
