# 耳朵算法（语音待命 / 语音识别）

> 2026-11-04 重写。目标是「该听的时候一定听得到，不该听的时候一句都不接」。
> 所有参数都可在浏览器控制台 `__chubbyWhale.ear` 里看实时值，便于按环境调。

## 一、为什么不能再用「频谱平均值 > 固定阈值」

旧实现：`getByteFrequencyData` 取平均 > 8 就算有声。

三个硬伤：

1. **量纲不对**：频谱平均是线性幅度，人耳和信噪比是对数的。安静房间和吵闹房间不能用同一个数。
2. **环境一变就失效**：空调开、风扇开、窗外车流，固定阈值要么疯狂误触发，要么完全听不见。
3. **单阈值必然二选一**：阈值高了漏掉轻声起头（句首被吃掉），阈值低了把句子中间的换气当成句末（句子被切断）。

## 二、现在的算法（四层）

### 第 0 层：浏览器自带 AEC / 降噪 / 自动增益

```js
getUserMedia({ audio: {
  echoCancellation: true,   // 回声消除：喇叭里的声音不进麦克风（最根本的一层）
  noiseSuppression: true,   // 降噪：稳态底噪先压一道
  autoGainControl: true,    // 自动增益：离得远也够响，不用主人提高音量
  channelCount: 1,          // 单声道：ASR 不需要立体声，省一半带宽
}})
```

这一层比任何后处理都准 —— 浏览器 AEC 拿得到「我正在播什么」这个参考信号。

### 第 1 层：能量测量用 dBFS

```
rms  = sqrt(mean(sample²))            // 时域 1024 点（≈21ms @48k）
dBFS = 20 * log10(rms + 1e-8)          // -160dB（全静音）… 0dB（满幅）
```

用 `getFloatTimeDomainData`，不再用频谱平均 —— RMS 跟响度线性对应，转 dB 后才有可比性。

### 第 2 层：自适应噪声底

```
安静时：noiseFloor = noiseFloor * 0.95 + dBFS * 0.05   // 指数滑动平均，慢速跟随
```

- 只在「当前判为安静」时更新，说话过程中不更新，避免把主人的声音学成噪声；
- 限幅在 `[-95dB, -20dB]`，防止全静音时漂到负无穷；
- 开机后有 400ms 标定期：这期间只学噪声、不判语音（否则一启动就被自己的启动声触发）。

### 第 3 层：双阈值滞回（hysteresis）

```
起判阈值 onset  = noiseFloor + 9dB      // 必须明显高于环境，防误触发
停判阈值 offset = noiseFloor + 5dB      // 回落到这里才算安静，防句子被切断
```

- 高于 onset：累计 `speechMs`；
- 低于 offset：累计 `quietMs`；
- 介于两者之间：保持当前状态（这就是「滞回」，避免阈值附近来回抖）。

判定说完：

```
speechMs >= 150ms  &&  quietMs >= 450ms     // 最短语音 + 静音收尾
或  整段 >= 6000ms                          // 兜底上限
```

`150ms` 是最短语音：咳嗽、键盘、关门声都过不了这一关。

## 三、防「自言自语」——回声判定

即使有浏览器 AEC，扬声器外放 + 房间混响仍可能漏一点回来。所以再加三道：

| 层 | 做法 |
| --- | --- |
| 播放期静音 | TTS 正在播 / TTS 队列非空 / 说书进行中 → 麦克风一律不上传 |
| 后置静音窗 | TTS 结束后 700ms 内不录音（等混响散掉） |
| 文本比对 | 记住最近 6 句自己说过的话；ASR 结果逐字命中 ≥60% 或互为子串 → 判为回声，丢弃并记日志 |

## 四、参数表（改动请同时更新这里）

| 参数 | 值 | 含义 | 调大的后果 |
| --- | --- | --- | --- |
| `ONSET_DB` | 9 | 起判高出噪声底多少 | 越大越不灵敏 |
| `OFFSET_DB` | 5 | 停判回落到哪 | 越大越容易提前收尾 |
| `MIN_SPEECH_MS` | 150 | 最短语音 | 越大越过滤杂音，但短句会被丢 |
| `SILENCE_LIMIT` | 450ms | 静音多久算说完 | 越大反应越慢 |
| `VOICE_LIMIT` | 5000ms | 单段最长录音 | 越大 ASR 越慢 |
| `CALIB_MS` | 400ms | 启动标定噪声底 | 越大启动越迟钝 |
| `ECHO_MUTE_MS` | 700ms | TTS 后静音窗 | 越大越不会自言自语，但接话变慢 |

## 五、怎么调（主人遇到问题时的自检）

浏览器控制台输入：

```js
__chubbyWhale.ear
// { db: -42.3, noiseDb: -61.2, onsetDb: -52.2, speechMs: 0, quietMs: 320, calibrating: false, ... }
```

判读：

| 现象 | 看哪个值 | 结论 |
| --- | --- | --- |
| 说话没反应 | `db` 说话时是否 > `onsetDb` | 不高于 → 离太远/麦克风被静音，先查系统输入音量和设备 |
| 噪声大时疯狂触发 | `noiseDb` 是否接近 `db` | 环境太吵，把 `ONSET_DB` 调到 12–15 |
| 句子被切一半 | `quietMs` 是否在句中就涨到 450 | 换气太长，把 `SILENCE_LIMIT` 调到 700 |
| 一句话要等很久 | `speechMs`/`quietMs` 到达判定点的耗时 | 网络慢多半是 ASR 段，看 `lastChatMs` |

## 六、已知边界（不吹牛）

- **AEC 依赖浏览器**：Chrome/Edge 支持良好；Safari 的 `echoCancellation` 实现较弱，外放仍可能回授。
- **没有做真正的双讲检测**：主人和鱼同时说话时，优先保证鱼不被自己的声音打断，代价是这期间主人插话会被忽略。
- **噪声底是全局单通道估计**：如果环境里有周期性敲击（机械键盘节奏），可能被学进噪声底，需要 `ONSET_DB` 调高。
- 本文参数基于常规室内近场使用，**未做多人/远场实测**；主人实际环境若不同，按第五节调。
