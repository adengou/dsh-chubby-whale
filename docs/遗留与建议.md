# 遗留与建议（审计"只报告未修"汇总）

> 本文件汇总 2026-11-06 无人值守迭代中，各分身审计后**只报告未修**的项。
> 每条都写了"为什么没修"或"要修需要动什么"，供后续批次按优先级处理。
> 原则：宁可少改，不可改出新 BUG；不确定的留在清单里。

## 一、按风险从高到低

### 1. 说书进度 key 没有数据源命名空间（中）
- **现象**：进度 key 是 `书|序号`，云端与本地同名书但内容/分段不同时，切数据源会跳段或重听。
- **为什么没修**：要改进度键协议并做旧数据迁移，属于跨版本数据变更。
- **修法**：key 改为 `source:书|序号`（`local`/`cloud`），启动时把旧 key 迁移一次。

### 2. 云端书单与正文的可用性不一致（中）
- **现象**：云端清单说 "17 本可用"，但某本正文拉不到时会逐本回退本地/空，`player` 跳过；用户看到书单有、点了没反应。
- **修法**：`listBooks` 对云端做一次轻量探活（或缓存上次失败列表），失败的书标注不可用。

### 3. ~~`estimateSpeakMs` 对英文/数字明显高估~~（**已修，2026-11-06**）
- **原现象**：`hello world` 估 5,860ms，实际约 1.2s。
- **已修**：中文按字（260ms，纯中文结果与旧值相等）、英文按词（300ms）、数字按位（200ms）；`hello world` 1200ms、`你好世界` 4040ms、`1324` 1400ms；单调性与有限性已验证，本地 `/tts` 实测对照见 `client/text.ts` 注释。
### 4. `x-client-id` 截断 64 位（低）
- **现象**：超长 id 会被截断，两个不同客户端可能共用一条连播队列。
- **修法**：id 生成端就限制在 64 位以内（客户端已随机生成，实际不触发）。

### 5. `cloud.ts` 忽略 index 的 `file` 字段（低）
- **现象**：按书名拼 `story/<书名>.json`，与云端命名不一致时静默回退本地。
- **修法**：优先读 `file` 字段，缺失才按书名拼。

### 6. 路由内部异常统一返回 200 `{ok:false,error}`（低，全仓约定）
- **现象**：HTTP 状态码不表达业务失败，监控只能看 body。
- **为什么没修**：客户端与测试都按这个约定写，改状态码要同步改两遍。

### 7. `player` 的模糊匹配会把 `../A` 解析成 `A`（低）
- **现象**：内部函数双向 indexOf 模糊匹配；HTTP 层已挡路径字符，内部无其他可达调用方。
- **修法**：匹配前先精确匹配书名，再退模糊；或禁止含 `/` 的输入（HTTP 层已做）。

### 8. `busy.end()` 无所有者/重入计数（低）
- **现象**：重复 `begin` 会重置计时；依赖上层 epoch 守卫，当前 UI 串行发送不触发。

### 9. `getJson` 不内置超时（低）
- **现象**：`chat`/`actions` 的 `getJson` 依赖浏览器默认超时；`poem-titles`/`story` 已自行传 `timeoutSignal`。

### 10. `apiUrl('/api')` 会重复前缀（低）
- **现象**：精确传 `/api` 会拼成 `/api/chubby-whale/api`；现有调用点不触发。

### 11. 菜单不抢焦点/无键盘导航、聊天框打开不自动聚焦（低，体验）
- **修法**：`render.ts` 的输入框加 ref + `autoFocus`；菜单项加 `tabIndex` 与方向键。

### 12. 三平台/三浏览器**真机**未验证（环境限制）
- **已做**：Windows + Chrome 实机；Linux/macOS/Safari/Firefox 只有 mock + stub。
- **补测清单**见 `docs/跨平台实测-20261106.md` 第五节。

### 13. `docs/坑.md` 中"坑 34/35"是远程维护者记的（已存在，未改）
- 本文件只补充坑 36–46，不覆盖历史。
