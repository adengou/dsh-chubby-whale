# 踩坑记录（务必先看这里）

> 2026-11-04 从零搭建 dsh-chubby-whale 过程中真实踩过的坑，按出现顺序记录。

## 坑 1：插件"消失"（dependencies/bundles 被清）

**现象**：页面 `Failed to load plugins` 或干脆不显示鱼。

**原因**：
- 有人执行了 `dsh plugin --profile web remove dsh-chubby-whale`，或 `dsh plugin --profile web install` 按 lockfile 同步时把 link 包清掉了；
- profile 的 `package.json` 里 `dependencies` 和 `dsh.profile.bundles` 都没了它，dsh 启动时静默跳过。

**排查**：
```powershell
# 看依赖和 bundles
(Get-Content <本机路径>\.dsh\profiles\web\package.json -Raw | ConvertFrom-Json).dependencies.'dsh-chubby-whale'
(Get-Content <本机路径>\.dsh\profiles\web\package.json -Raw | ConvertFrom-Json).dsh.profile.bundles
# 看链接
Test-Path <本机路径>\.dsh\profiles\web\node_modules\dsh-chubby-whale
# 插件接口是否 404（没加载）
curl http://127.0.0.1:3080/api/chubby-whale/status
```

**修复**：
```powershell
dsh plugin --profile web add "link:<本机路径>\.dsh\plugins\dsh-chubby-whale"
# 然后重启 dsh web
```

## 坑 2：client.js 带 import（浏览器 import failed）

**现象**：`dsh-chubby-whale: import failed: client-modules: require("./client/styles.js") missed the module table` 或 `import failed (see console for the import error)`。

**原因**：
- 源码模块化后，`client.ts` 顶部有 ESM import；
- `tsc` 把 `src/client.ts` 编译成 `dist/client.js`（保留 import），**覆盖**了 esbuild 的打包产物；
- 浏览器直接加载带 import 的脚本 → 失败。

**修复**：
- `tsconfig.json` 的 `exclude` 加 `"src/client.ts", "src/client/**"`（tsc 只编 host）；
- client 只由 esbuild 打包：`esbuild src/client.ts --bundle --format=iife --external:react --outfile=dist/client.js`；
- 检查产物：`Select-String dist/client.js -Pattern '^import '` 应无结果。

## 坑 3：两处 inject 别混淆（最致命）

- `package.json` 的 `dsh.client.inject` 填**包名**：`@deepseek-ai/dsh-client-ui-slots`（加载顺序）；
- `client.js` 导出的 `inject` 填**服务名**：`['slots']`（激活时机）；
- 填反或都用 `slots` → `web boot: 1 entry did not activate` → **整个网页打不开**（DSH 全有或全无）。

## 坑 4：web 启动 EADDRINUSE

- 旧 web 进程占 3080，新进程起不来；
- 排查：`netstat -ano | findstr :3080` 找 LISTENING 的 PID，杀掉再启动。

## 坑 5：重启后 401（认证）

- `dsh web` 每次启动打印带 `?token=...` 的 URL；
- 页面/接口需要该 token（cookie）；API 接口在浏览器同源请求里带 cookie 即可；
- 命令行 curl 无 cookie 会被 401（正常）。

## 坑 6：Start-Process 日志重定向不稳定

- `Start-Process -RedirectStandardOutput` 有时不生成日志文件；
- 拿不到 web 启动 token 时，直接让主人在终端跑 `dsh web`（打印 URL），或读进程 stdout。

## 坑 7：说书气泡挡脸 / 三角不显示

- 气泡定位在鱼上方会挡住头 → 挪到鱼左上（x-270）；
- 气泡 `overflow-y: auto` 会把外侧三角裁掉 → 三角用 CSS 伪元素（`.chubby-bubble::after`）；
- 说书正文太长 → 只显示"正在讲《X》回目…"状态，正文用 TTS 念。

## 坑 8：修改后必须按顺序构建

```powershell
cd <本机路径>\.dsh\plugins\dsh-chubby-whale
npm run build   # tsc -p tsconfig.json && esbuild src/client.ts ...
```

- 只跑 tsc 会把 client 编成带 import 的版本（坑 2 复现）；
- 构建后重启 `dsh web` 才生效。

## 坑 9：**插槽 register 的第二个参数必须是渲染函数**（2026-11-04 实测，曾导致整个 harness 页面闪退）

**现象**：装上插件后页面直接闪退/白屏，控制台报 `Invalid hook call`（或 React 渲染树崩），`dsh web` 进程本身没死。

**错误写法**（会崩）：
```ts
ctx.slots.register({ name: 'shell.overlay', id: 'chubby-whale', order: 100 }, WhaleOverlay)
//                                                                          ↑ 直接把组件传进去
```

**正确写法**：
```ts
ctx.slots.register(
  { name: 'shell.overlay', id: 'chubby-whale-overlay', order: 999 },
  () => React.createElement(WhaleOverlay, {}),   // ← 必须包一层渲染函数
)
```

**原因**：宿主把第二个参数当"渲染函数"调用，不是在 React 组件树里渲染组件。
直接传组件 = 在渲染上下文之外调用组件函数，组件内第一句 `useState`/`useEffect`
立即抛 `Invalid hook call`，异常冒泡把 harness 外壳一起带崩（表现为"闪退"）。

**必须同时做的防护**（照 `dsh-dafeiyu` 的做法）：
```ts
const registerOverlay = () => {
  try {
    ctx.slots.register({ name: 'shell.overlay', id: 'xxx-overlay', order: 999 }, () => React.createElement(Comp, {}))
  } catch (e) { console.error('[xxx] overlay 注册失败：', e) }   // 只让浮层不显示，绝不拖垮页面
}
try { ctx.slots.inject('shell.overlay', registerOverlay) }
catch (e) { console.error('[xxx] overlay 注入失败：', e) }
```

**自检**：`ctx.slots.register(a, b)` 里的 `b` 必须是一个**无参函数**，返回 React 元素。

## 坑 10：宿主端 `apply` 的配置是第二个参数，不是 `ctx.config`

- `apply(ctx, config)` ← 配置在第二个参数（来自 `cordis.patch.yml` 的 `config:` 段）；
- 写 `ctx.config.xxx` 会抛 `cannot get property "config" without inject`，插件整块失效；
- 想读开关就写 `export function apply(ctx, config) { if (config?.enabled === false) return }`。

## 坑 11：`register()` 的返回值是 disposer，必须托管

- `ctx.webServer.register(route)` 返回一个删除该路由的函数，同一 path 再注册会 **throw duplicate**；
- 不收集 disposer → 热重载/禁用再启用时 `apply` 第二次执行直接抛错，插件整块失效；
- 正确姿势：
  ```ts
  const disposers: Array<() => void> = []
  const reg = (path: string, handler: any) => {
    const d = ctx.webServer.register({ kind: 'exact', path, handler })
    if (typeof d === 'function') disposers.push(d)
  }
  ctx.effect(() => { reg('/api/x/y', h); return () => disposers.forEach((d) => d()) })
  ```
- `ctx.on('dispose')` **不存在**（cordis 没有这个事件），别写。

## 坑 12：别用「命令行里出现关键词」的方式杀进程

- `Where-Object { $_.CommandLine -match 'asr-listener' }` 会把**执行这条命令的 shell 自己**也数进去并杀掉 → 命令自己莫名退出（exit code 4294967295）；
- 正确姿势：按进程名过滤，或用 `-and $_.ProcessId -ne $PID` 并排除父进程；杀掉前先打印 PID 与命令行核对。

## 坑 13：插件自己读 Key，别读 DSH 全局凭据

- 读 `~/.dsh/.credentials.yaml` 会与其他插件/宿主耦合（别人换 Key 会牵连你）；
- 推荐顺序：本插件 `config.json` → 插件专属环境变量（如 `CHUBBY_WHALE_DEEPSEEK_KEY`）→ 通用名兜底；
- 运行数据也放插件自己的目录（本插件用 `~/.dsh-chubby-whale`），别写进插件包，否则升级重装丢数据。
