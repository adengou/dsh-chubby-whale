## 0. 名称与定位

**鲸群营造（WhaleWorks）** 是工程方法名。

**鲸群施工队** 是一次具体施工。

```text
鲸群营造 = 方法 / 流程 / 组织方式
鲸群施工队 = 按这套方法跑的一次项目
```

一句话：

> 总监立项，包工头带工人，验收官签字，小鲸驻场看板；  
> 工人完成 ≠ 包工头完成 ≠ 验收通过 ≠ 总监收工。

### 历史 v0.1（已从产品移除）

- 曾实现 `whale-works.ts` 施工检查器、脚下施工摘要、右键「施工队 ▸」模板菜单；
- 因不具用户价值，已按主人要求移除用户入口与检查器；本文仅保留方法存档，不再描述为可用功能。

## 1. 要解决的问题

多 Agent 工程常见问题：

- 派活容易，收口难；
- 任务板显示“完成”，但没有证据；
- 多个 Agent 同时改同一文件，互相覆盖；
- 总监直接带十几个工人，变成人肉调度器；
- 验收官和施工方是同一个人，自己验自己；
- 完成后没有竣工包，只有聊天记录；
- 主人不知道现在到哪一步，只能反复问。

鲸群营造用五层组织解决：

```text
总监 → 包工头 → 工人 → 任务清单 → 验收官
                 ↑
              小鲸（只读监理）
```

## 2. 组织拓扑

```text
主人
  ⇅
小鲸（驻场监理 / 项目秘书）
  │  只读任务板 + 消息 + 证据
  │  只向主人汇报、向总监提醒
  ↓
总监（Director / Lead）
 ├─ 包工头 A（Branch Foreman）→ 工人 A1/A2/A3
 ├─ 包工头 B（Branch Foreman）→ 工人 B1/B2
 ├─ 包工头 C（Branch Foreman）→ 工人 C1
 └─ 验收官（Verifier，独立）
```

### 指挥链与观察链

```text
指挥链：主人 → 总监 → 包工头 → 工人
验收链：验收官 → 总监 → 主人
观察链：小鲸 ← 任务板/消息/证据（只读）
提醒链：小鲸 → 总监（提醒，不命令）
```

小鲸**不在指挥链上**，没有 claim / complete / reassign 权限。  
她的权力只有两个：**看得见**、**说得上话**。

## 3. 角色职责

### 3.1 总监（Director / Lead）

做：

- 写 Team Brief：目标、范围、验收、预算、截止时间；
- 拆工作流与分支；
- 创建分支任务、验收任务、汇总任务；
- 启动包工头与验收官；
- 处理跨分支阻塞、共享文件冲突；
- 集成、跑全链、发版；
- 最终签字与收工。

不做：

- 不替包工头带工人；
- 不盯每个叶子任务；
- 不跳过验收官直接发版；
- 不把“工人说完成”当成验收通过。

### 3.2 包工头（Foreman）

做：

- 认领分支任务；
- 把分支拆成工人叶子任务（工卡）；
- 给工人任务 id、scope、验收、证据要求；
- 监督本分支进度；
- 合拢本分支结果；
- 向总监报验。

不做：

- 不跨分支施工；
- 不越 write scope；
- 不跳过验收；
- 不替工人补证据。

### 3.3 工人（Worker）

做：

- 认领叶子任务；
- 按工卡施工；
- 只改自己的 write scope；
- 交证据；
- complete 并上报包工头。

不做：

- 不跨 scope；
- 不自称验收；
- 不替别的工人完成。

### 3.4 验收官（Verifier）

做：

- 独立读任务板、工卡、证据、产物；
- 复跑/抽查；
- 写验收报告；
- 通过则 complete 验收任务；
- 不通过则建缺陷任务，退回包工头。

不做：

- 不修代码；
- 不帮工人补证据；
- 不参与施工；
- 不拿“completed”当“accepted”。

### 3.5 小鲸（Clerk of Works）

做：

- 脚下看板：分支/工人/阶段/卡点/待补证；
- 冒泡：审批、卡住、写作用域重叠、验收未签字；
- 向总监提醒“该催 A 了”；
- 给主人解释进度；
- 汇总竣工包/复盘摘要；
- 收工动作。

不做：

- 不 claim/complete/reassign 任务；
- 不直接命令包工头/工人；
- 不替验收官签字；
- 不替总监做决定；
- 后台不自动改任务板。

## 4. RACI

| 事项 | 主人 | 小鲸 | 总监 | 包工头 | 工人 | 验收官 |
|---|---|---|---|---|---|---|
| 目标/预算 | A | C | R | I | I | I |
| 拆分支 | I | I | A/R | C | — | — |
| 分支施工 | I | I | A | R | R | — |
| 叶子任务 | I | I | I | A | R | — |
| 集成 | I | I | A/R | C | C | — |
| 验收 | A | I | C | C | I | R |
| 发版 | A | C | R | I | I | C |
| 收工 | A | C | R | I | I | C |

`A=最终负责，R=执行，C=被咨询，I=被告知`

## 5. 工程生命周期

```text
立项 → 设计 → 拆任务 → 分支施工 → 集成 → 独立验收 → 发版 → 复盘
```

| 阶段 | 总监 | 包工头 | 工人 | 验收官 | 小鲸 | 产出 | 闸门 |
|---|---|---|---|---|---|---|---|
| 0 立项 | 写 Brief、定预算 | 不参与 | 不参与 | 不参与 | 显示「立项中」 | `team/brief.md` | G0 |
| 1 设计 | 定边界、派设计分支 | 设计包工头出方案 | 设计工人查资料/画流程 | 可做设计评审 | 显示「设计评审」 | `design/contract.md` | G1 |
| 2 拆任务 | 建 epic/分支/验收任务 | 拆叶子工卡 | 不参与 | 检查 DAG | 显示「待开工」 | 任务板 + 工卡 | G2 |
| 3 分支施工 | 处理跨分支阻塞 | 管本分支、合拢 | 按工卡施工、交证据 | 不参与 | 脚下看板 | 代码 + evidence | G3 |
| 4 集成 | 合代码、跑全链 | 修本分支问题 | 修叶子问题 | 不参与 | 显示「集成中」 | 集成分支 + 全链测试 | G4 |
| 5 验收 | 提交验收 | 提供证据 | 配合复现 | 独立复跑/抽查 | 显示「待验收」 | `team/verification.md` | G5 |
| 6 发版 | 版本、tag、三仓库 | 不参与 | 不参与 | 可抽查发布物 | 显示「发版中」→「鲸群回巢」 | release notes + tag | G6 |
| 7 复盘 | 主持复盘 | 写分支复盘 | 提供问题 | 给验收结论 | 汇总「本次施工」 | `team/retro.md` | G7 |

## 6. 闸门定义

```text
G0 立项：Brief 有目标/范围/验收/预算，主人批准
G1 设计：接口/边界/失败路径清楚，契约冻结
G2 任务：DAG 无环、scope 不重叠、叶子有工卡
G3 分支：本分支测试通过、证据齐全
G4 集成：全链测试通过、无未解决冲突
G5 验收：验收官独立复跑，签字
G6 发版：版本/tag/三仓库/桌面 profile 一致
G7 复盘：返工/缺陷/假设记录归档
```

任何一关不过：

```text
验收不通过 → [FIX] 缺陷任务 → 原包工头返工 → 验收官重验 → 总监再集成
```

不允许：

- 工人自报完成就算验收；
- 包工头跳过验收直接发版；
- 小鲸替验收官签字；
- 任务 completed 冒充 accepted。

## 7. 任务清单规范

### 7.1 标题前缀

```text
[E]  工程/史诗
[D]  设计/总监级
[A]  分支 A
[A1] 分支 A 的工人任务
[V]  验收
[R]  发版
[X]  复盘
[FIX] 缺陷返工
```

真实 task id 仍由 `team_task_create` 生成；前缀只用于识别层级。

### 7.2 任务描述模板

```text
[任务类型] 分支/任务名
目标：
输入：
输出：
写作用域：
依赖：
验收标准：
证据要求：
禁止事项：
上报对象：
```

### 7.3 叶子工卡模板

```text
任务标题：
父分支：
执行人：
任务 id：
目标：
输入：
输出：
写作用域：
禁止事项：
验收标准：
证据要求：
上报对象：
完成条件：
```

工卡正文放 `team/briefs/<task-id>.md`；任务 description 只放一行链接，避免任务板被长文撑爆。

### 7.4 关键规则：父级前缀 ≠ blockedBy

错误：

```text
[A] 分支任务
[A1] 工人任务 blockedBy [A]   ← 死锁
```

正确：

```text
[A]   分支跟踪任务，不参与叶子 block
[A1]  blockedBy: 无，或只依赖真实前置叶子
[A]   complete 条件：A1/A2 都完成
```

`blockedBy` 只表达真实工作依赖，不表达父子层级。  
父子层级用标题前缀和工卡里的“父分支”表达。

## 8. 写作用域

```text
设计包工头：design/**、docs/design/**
前端包工头：src/client/**、src/shared/**（前端相关）、scripts/test-client-*
宿主包工头：src/host/**、src/shared/**（宿主相关）、scripts/test-host-*
QA 包工头：scripts/test-*、docs/**、CHANGELOG.md 草稿
总监：src/client.ts、package.json、tag、发布物
验收官：team/verification.md（只写验收报告）
小鲸：无写权限
```

冲突规则：

- `src/client.ts`、`package.json`、`CHANGELOG.md` 是共享中央文件，默认只由总监改；
- 包工头需要改中央文件时，必须先向总监申请，同一时间只允许一个分支改；
- `writeScopes` 是 advisory，不是锁；总监负责最终冲突检查。

## 9. 工程任务 DAG 示例

```text
[E] 本次工程（总监）
 ├─ [D] 设计契约（设计包工头）
 │    └─ [D1] 方案/边界/接口（设计工人）
 ├─ [F] 前端实现（前端包工头，依赖 [D]）
 │    ├─ [F1] UI/交互（前端工人）
 │    └─ [F2] 前端测试（前端工人）
 ├─ [H] 宿主实现（宿主包工头，依赖 [D]）
 │    ├─ [H1] 路由/存储（宿主工人）
 │    └─ [H2] 宿主测试（宿主工人）
 ├─ [Q] 测试与文档（QA 包工头，依赖 [F]/[H]）
 │    ├─ [Q1] 全链测试
 │    └─ [Q2] 文档/CHANGELOG 草稿
 ├─ [I] 集成（总监，依赖 [F]/[H]/[Q]）
 ├─ [V] 独立验收（验收官，依赖 [I]）
 ├─ [R] 发版（总监，依赖 [V]）
 └─ [X] 复盘（总监，依赖 [R]）
```

## 10. 小规模示例：文件清单 + 格式检查

```text
[D] 本次小协作
  ├─ [A] 文件清单（总监创建，包工头 A 跟踪）
  │    ├─ [A1] 顶层文件清单（工人 A1）
  │    └─ [A2] 清单校验（工人 A2，依赖 A1）
  ├─ [B] 格式检查（总监创建，包工头 B 跟踪，依赖 A）
  │    └─ [B1] AGENTS.md 格式（工人 B1）
  ├─ [V] 独立验收（依赖 A、B）
  └─ [D-FINAL] 总监汇总（依赖 V）
```

叶子工卡：

- A1：列出当前目录顶层文件；输出 `team/evidence/A1.md`；只读，不改业务文件；
- A2：校验 A1 总数/重复/排序；输出 `team/evidence/A2.md`；
- B1：检查 `AGENTS.md` 编码/BOM/行尾/标题层级；只读，不改文件；
- V：独立复跑，写 `team/verification.md`。

## 12. 竣工包

```text
team/
  brief.md            工程目标与验收
  verification.md     验收报告
  retro.md            复盘
  evidence/           证据
  briefs/             叶子工卡
  report.md           最终交付说明
```

竣工包必须包含：

- 目标与验收结论；
- 任务清单与完成状态；
- 证据索引；
- 未决问题/风险；
- 返工记录；
- 版本/tag/发布物。

## 13. 失败与返工

| 情况 | 处理 |
|---|---|
| 包工头卡住 | 总监发消息；超时则换人/拆小任务 |
| 工人失联 | 包工头回收任务，重新分配；官方不会自动释放 owner，需显式改派 |
| 写作用域重叠 | 总监调整 scope；advisory，不是锁 |
| 验收不通过 | 建 `[FIX]` 缺陷任务，退回包工头；不直接改 completed |
| 分支太多 | 合并为 2～3 个包工头；避免层级超过 3 层 |
| 成本过高 | 限制工人数、轮次、是否启用搜索/OCR |
| 任务板无数据 | 小鲸降级为“只看任务板”，不伪造 |

---

## 14. 不做什么

- 不自动改任务板；
- 不自动创建任务（除非主人明确要求“组队/开工”）；
- 不替主人做决策；
- 不绕过验收；
- 不把角色扮演当证据；
- 不为了“多 Agent”而多 Agent。

## 16. 验收清单（模板自身）

- [ ] 总监、包工头、工人、验收官、小鲸职责清楚；
- [ ] 每个叶子任务有工卡，不是一句话；
- [ ] `blockedBy` 无父子死锁；
- [ ] 写作用域不重叠，共享文件归总监；
- [ ] completed ≠ accepted；
- [ ] 验收官独立，不参与施工；
- [ ] 小鲸只读，不碰任务板；
- [ ] 竣工包含证据/验收/复盘；
- [ ] 失败有返工路径；
- [ ] 全流程可追踪、可审计。
